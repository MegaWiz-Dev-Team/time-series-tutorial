Telling central from obstructive apnea: how we benchmarked and tuned the detector

A walkthrough of the whole investigation — the problem, the data, how we measure, every tuning approach we tried, and how we checked we weren't fooling ourselves. Written to be read start to finish.

เอกสารนี้เล่าทั้งกระบวนการตั้งแต่โจทย์ → ข้อมูล → วิธีวัดผล → วิธีปรับจูนแบบต่างๆ → การตรวจสอบว่าไม่ได้หลอกตัวเอง เขียนให้อ่านไล่ตั้งแต่ต้นจนจบ เหมาะกับคนที่เพิ่งเริ่ม (นศ. วิศวะคอม ปี 1 / วิศวะการแพทย์ ปี 3). ศัพท์เทคนิคมีอธิบายใน Glossary ท้ายเอกสาร

1The clinical problem

Sleep apnea is when breathing repeatedly stops during sleep. There are two kinds that look almost the same on a breathing trace but need opposite treatments:

  • Obstructive apnea — the airway collapses, but the brain still tries to breathe. The chest keeps moving (effort continues) while airflow stops. Treated with CPAP (air pressure to hold the airway open).
  • Central apnea — the brain stops sending the signal to breathe. Airflow stops and the chest stops moving (no effort). Often a sign of a heart problem → needs cardiac work-up, not plain CPAP.

So the machine's job is: for each apnea, decide obstructive or central. Getting central wrong can send a heart patient down the wrong path.

โจทย์: ภาวะหยุดหายใจขณะหลับมี 2 แบบที่หน้าตาคล้ายกันมากแต่รักษาคนละทาง — Obstructive (ทางเดินหายใจตีบ แต่สมองยังสั่งให้หายใจ → อกยังขยับ) รักษาด้วย CPAP; Central (สมองหยุดสั่งหายใจ → อกไม่ขยับเลย) มักโยงโรคหัวใจ ต้องส่งตรวจหัวใจ ไม่ใช่ CPAP ธรรมดา งานของตัว detector คือแยกให้ถูกว่าเป็นแบบไหน เพราะถ้าพลาด central อาจส่งคนไข้หัวใจไปผิดทาง

2The device constraint & the shipped rule

Our product (Nótt) runs on a Type-3 home sleep test (ResMed ApneaLink). That means a small set of signals — nasal flow, one chest effort belt, blood-oxygen SpO₂, and pulse — and crucially no EEG (no brain-wave channel, unlike a full lab sleep study). With one effort belt, the only real clue for central-vs-obstructive is: did chest effort disappear?

The shipped detector (detect.rs) uses a simple rule. It measures how much the effort signal is moving during the apnea, as a ratio to the patient's typical breathing:

# effort "energy" during the apnea, relative to a whole-night reference
rt = variance(effort during apnea) / night_reference
if rt < 0.15:  # effort nearly gone → call it CENTRAL
    central
else:          # effort still present → OBSTRUCTIVE
    obstructive

One number (rt), one threshold (0.15). It's a reasonable first cut, and it's what we're trying to beat.

ข้อจำกัดเครื่อง: Nótt เป็น Home Sleep Test แบบ Type-3 — มีแค่ flow / effort (สายอกเส้นเดียว) / SpO₂ / pulse และไม่มี EEG (คลื่นสมอง) เหมือน sleep lab เต็มรูปแบบ ดังนั้นเบาะแสเดียวของ central-vs-obstructive คือ "อกหยุดขยับไหม"
กฎเดิมใน detect.rs: คิด rt = variance ของ effort ช่วงหยุดหายใจ ÷ ค่าอ้างอิงทั้งคืน ถ้า rt < 0.15 (แรงหายใจแทบหาย) = central เป็นกฎ threshold เดียว ที่เราจะพยายามทำให้ดีกว่า

3Building the benchmark data

You can't tune what you can't measure, and you can't measure on 15 patients. We grew the test set by pulling real diagnostic studies from the clinic's ResMed AirView account, anonymized at the source (patient name / IDs scrubbed out of every file before it left, stored under a random token with no way back to a person). Each study gives us the raw waveforms plus AirView's own event scoring.

Why it matters: central apnea is rare. In the old 15-patient set, 60% of all central events came from a single patient — so any result could just be memorizing that one person. The pull spread central events across 80 patients, dropping that concentration to 33%. That diversity is what makes the benchmark trustworthy.

One honest caveat carried through everything below: our labels are AirView's automatic scoring (we call this “bronze” quality) — good, but not a doctor's hand-scoring. So every score is really “agreement with AirView,” an upper bound on what the machine could reach if the labels were perfect.

ข้อมูล: ปรับจูนได้ต้องวัดได้ และวัดบน 15 คนไม่พอ เราจึงดึง sleep study จริงจาก ResMed AirView ของคลินิก (ลบตัวตนตั้งแต่ต้นทาง — ชื่อ/ID ถูก scrub ออกทุกไฟล์ก่อนออกจากระบบ เก็บด้วย token สุ่ม ย้อนกลับไปหาคนไม่ได้)
สำคัญ: central เป็น event ที่หายาก — ชุด 15 คนเดิม 60% ของ central มาจากคนเดียว (ผลอาจแค่ "จำ" คนนั้น) การดึงเพิ่มทำให้ central กระจายไป 80 คน (กระจุกเหลือ 33%) → benchmark เชื่อถือได้ขึ้น
ข้อควรรู้: label เป็น auto-scoring ของ AirView (เรียก bronze) ไม่ใช่หมอ score เอง ดังนั้นทุกคะแนนคือ "ตรงกับ AirView แค่ไหน" = เพดานบน

4How we measure — the benchmark method

Two ideas do all the heavy lifting here. Get these and the rest is easy.

Leave-One-Patient-Out (LOPO)

To test whether a model generalizes to a new patient, you must never let it see that patient during training. So we train on 118 patients and test on the 1 left out — then repeat, holding out each patient in turn, and pool the results. If instead you let one patient's events land in both training and test, the model can cheat by memorizing that person (this mistake is called data leakage), and your numbers look great but mean nothing on real new patients.

LOPO (แยกทีละคนออกไปทดสอบ): จะรู้ว่าโมเดลใช้กับคนใหม่ได้ไหม ต้องไม่ให้มันเห็นคนนั้นตอนเทรน เราจึงเทรนด้วย 118 คน เทสต์คนที่กันไว้ 1 คน แล้ววนกันออกทีละคนจนครบ ถ้าปล่อยให้ event ของคนเดียวกันอยู่ทั้งฝั่งเทรนและเทสต์ โมเดลจะโกงด้วยการจำคนนั้น (เรียก data leakage) — ตัวเลขสวยแต่ใช้กับคนจริงไม่ได้

The metrics — and why not plain accuracy

Our data is 9,065 obstructive vs 647 central. A lazy model that shouts “obstructive!” every time is ~90% accurate and 100% useless — it never finds a central. So we use:

  • Balanced accuracy — the average of each class's recall, so the rare central class counts as much as the common obstructive one. (Random guessing on 3 classes ≈ 0.33.)
  • Central recall — of all true central apneas, what fraction did we catch? This is the one that matters clinically.
  • Obstr→central — of obstructive apneas, what fraction did we wrongly call central? This is the harm: over-calling central sends the wrong patients for a heart work-up.
ตัวชี้วัด: ข้อมูลเรา 9,065 obstructive : 647 central ถ้าโมเดลขี้เกียจตอบ "obstructive" ทุกครั้ง จะแม่น ~90% แต่ไร้ประโยชน์ (ไม่เจอ central เลย) เราจึงใช้ Balanced accuracy (เฉลี่ย recall ทุก class ให้ central ที่หายากมีน้ำหนักเท่า obstructive; เดามั่ว 3 class ≈ 0.33), Central recall (จับ central จริงได้กี่ % = ตัวสำคัญทางคลินิก), และ Obstr→central (obstructive ที่ถูกเรียก central ผิด = ความเสียหาย)

5The tuning approaches we tried

Three approaches, in order. Each answered a question and pointed to the next.

A — Just tune the threshold

Keep the shipped rule, but sweep the 0.15 threshold across many values and pick the best. Result: it doesn't help. Raising the threshold catches more central but also over-calls far more obstructive — a fixed trade-off on one curve. Best balanced accuracy stayed at 0.544. Adding the diverse 140 patients confirmed this ceiling rather than breaking it — both cohorts agreed, so it's a real limit, not a small-sample fluke.

B — Same features, but a learned model

The rule uses only rt. But the detector already computes two more numbers — effort in the first vs second half of the event (rf, rs). Feed all three to a small machine-learning classifier (which learns a curved boundary using them jointly, weighting the rare class up) instead of one hand-set threshold. Balanced accuracy jumped to ~0.61–0.65 — same information, used better. Lesson: the single-threshold rule was leaving signal on the table.

C — Engineer new features from the raw signal

Then we computed new features from the stored waveforms and tested each family: effort timing (how effort varies across four quarters of the event), flow shape, hypoxic burden / SpO₂ (depth and timing of oxygen dips), pulse (heart-rate surge = arousal), and flow–effort coupling. Only one family moved the needle — and it moved it a lot.

วิธีปรับจูน 3 แบบ: A) จูน threshold อย่างเดียว → ไม่ช่วย (ติดเพดาน 0.544 เพราะเพิ่ม central ก็ over-call obstructive ตามมา; ข้อมูล 140 คนใหม่ยืนยันเพดานนี้ ไม่ใช่ทำลาย) B) feature เดิม 3 ตัว (rt + ครึ่งแรก rf + ครึ่งหลัง rs) แต่ใช้โมเดลเรียนรู้แทนกฎ → พุ่งเป็น 0.61–0.65 (ข้อมูลเท่าเดิม ใช้ดีขึ้น) C) สร้าง feature ใหม่จากสัญญาณดิบ แล้วทดสอบทีละกลุ่ม → มีแค่ effort timing (แบ่ง event เป็น 4 ช่วง ดูว่าแรงหายใจโผล่ช่วงไหน) ที่ช่วยจริง → 0.67–0.76 เหตุผล: central = ไม่มีแรงหายใจทุกช่วง; obstructive = แรงหายใจกลับมาช่วงกลาง — rt ตัวเดียวเฉลี่ยทั้ง event เลยกลืน timing นี้หาย; flow/SpO₂/pulse บน belt เดียวไม่ได้เพิ่มข้อมูล กลายเป็น noise

6Checking we didn't fool ourselves

A big jump is exactly when you should be suspicious. Three adversarial checks — designed to break the result, not confirm it:

  • Leakage test (shuffle). Randomly shuffle the labels so features and answers no longer match, then re-run. If the score stays high, the model was cheating. It collapsed to 0.338 (≈ random) → no leakage; the signal is real.
  • Robustness. Re-run with five different models/seeds. The improvement held in every one (they agreed within 0.007) → not a lucky fluke. But the exact 0.76 only appeared with one well-regularized model; the default gave 0.67.
  • Label-noise. Maybe AirView mislabels some central? We checked: only 1.1% of central events have clear effort. Removing them changed the score by ±0.002 → the labels are clean; the ceiling wasn't noise.

So the honest conclusion: the improvement is real, leak-free, and robust in direction — but the headline number is config-dependent. We report the reliable lift (+0.07 balanced acc, +0.15 central recall) and a range (0.67–0.76), never a single hero number.

ตรวจสอบว่าไม่หลอกตัวเอง (ยิ่งผลกระโดดยิ่งต้องระแวง) ทำ 3 การทดสอบที่ตั้งใจ "หักล้าง" ผล: 1) Shuffle test — สลับ label มั่ว ถ้าคะแนนยังสูง = โกง; ผลตกไป 0.338 (เท่าเดา) = ไม่มี leak 2) Robustness — ลอง 5 โมเดล/seed ดีขึ้นทุกตัว (ต่างกันแค่ 0.007) แต่ 0.76 ได้เฉพาะโมเดล regularized ดีๆ; default ได้ 0.67 3) Label-noise — central ที่ label น่าสงสัยมีแค่ 1.1% ตัดออกคะแนนขยับ ±0.002 = label สะอาด
สรุปอย่างซื่อสัตย์: ผลจริง ไม่ leak robust แต่ตัวเลขขึ้นกับ config → รายงานเป็นช่วง 0.67–0.76 + lift ที่เชื่อได้ (+0.07) ไม่ยกตัวเลขเดียวมาโม้

7What to take away & do next

  • The single-threshold rule under-uses the signal. A learned model on effort timing lifts central recall from 0.57 to ~0.72–0.82 with far fewer false alarms — a real clinical win on the class that matters.
  • Size it honestly: ~0.67–0.72 balanced accuracy, not 0.76–0.82. Trust the direction; pin the model configuration and validate on patient-disjoint folds before it becomes an official number.
  • Port the effort-quartile features into detect.rs (Rust) and swap the threshold for the learned model.
  • Then chase the label ceiling: pull doctor/technician (“silver/gold”) labels to see how much higher the true ceiling is once AirView's noise is removed.
สรุป & ทำต่อ: กฎ threshold เดียวใช้สัญญาณไม่คุ้ม — โมเดลบน effort timing ดัน central recall 0.57 → 0.72–0.82 พร้อม false alarm น้อยลงมาก (1) ตั้งความคาดหวังที่ ~0.67–0.72 อย่างซื่อสัตย์ (ไม่ใช่ 0.76) + pin config + validate แบบ patient-disjoint ก่อนประกาศ (2) port feature effort-quartile เข้า detect.rs (Rust) แล้วเปลี่ยนจาก threshold → learned model (3) ดึง label หมอ/นักเทคนิค (silver/gold) ดูเพดานจริงเมื่อตัด noise ของ AirView

8Glossary

EDF
European Data Format — the standard file for raw biomedical time-series (our waveforms live here).ไฟล์มาตรฐานเก็บสัญญาณชีวการแพทย์แบบ time-series
Effort (RIP belt)
A stretchy belt around the chest that measures breathing effort by how much the chest expands.สายรัดอกวัด "แรงพยายามหายใจ" จากการขยายของทรวงอก
Feature
A number computed from the raw signal that the model reads (e.g. effort variance in a quarter of the event).ตัวเลขที่คำนวณจากสัญญาณดิบเพื่อป้อนโมเดล
Class imbalance
When one class (obstructive) vastly outnumbers another (central). Breaks plain accuracy.คลาสหนึ่งเยอะกว่าอีกคลาสมาก ทำให้ accuracy ธรรมดาใช้ไม่ได้
Balanced accuracy
Average recall across classes, so a rare class counts equally.เฉลี่ย recall ทุกคลาส ให้คลาสหายากมีน้ำหนักเท่ากัน
Recall
Of the true cases of a class, the fraction the model caught.ในของจริงคลาสนั้น โมเดลจับได้กี่ %
LOPO-CV
Leave-One-Patient-Out cross-validation — test on a patient the model never trained on.เทสต์บนคนที่โมเดลไม่เคยเห็นตอนเทรน
Data leakage
When test information sneaks into training, inflating scores dishonestly.ข้อมูลเทสต์รั่วเข้าไปในการเทรน ทำให้คะแนนสูงแบบหลอกๆ
Overfitting
A model that memorizes training quirks instead of learning the general pattern.โมเดลจำรายละเอียดชุดเทรนแทนที่จะเรียนรู้แพตเทิร์นทั่วไป
Ablation
Adding/removing one feature group at a time to see what actually helps.ใส่/ถอด feature ทีละกลุ่มเพื่อดูว่าอันไหนช่วยจริง
Hypoxic Burden
How deep and long blood-oxygen dips during events — a heart-risk marker.ความลึก×นานของการที่ออกซิเจนตก ระหว่าง event = ตัวชี้ความเสี่ยงหัวใจ

9Reproduce it yourself

Everything is scripted. The scripts run under a Python venv with numpy scipy scikit-learn pyedflib; data is on disk and in MariaDB.

# 1. features → per-event feature matrix (10,014 × 22) from the raw npz
python feature_engineer.py        # writes features.npz
# 2. the benchmark: LOPO ablation across feature families + 2 models
python lopo_ablation.py           # prints the results table
# 3. threshold-only tuning (approach A), for comparison
python tune_effort_ratio.py
